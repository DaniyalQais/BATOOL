## What the shared limit means

The database uses fixed clock-minute windows. All shoppers share **30 availability requests/minute** and a separate **30 checkout/guest-recovery requests/minute**, beneath a **120/minute global ceiling**. Availability page loads/manual refreshes compete; a 31st admitted request in that cohort is throttled. A typical new purchase uses scope + quote + create: three checkout requests, yielding an ideal ceiling of **10 fresh purchases/minute**, before abandonment, retries, expired-intent replacement or recovery. This arithmetic is not a load-test result. Internal database calls within an Edge action do not consume additional Edge admissions.

Rejected cohort requests still increment the global counter. One noisy caller can exhaust shared availability, ordering and recovery capacity for others. Waiting until the next database minute can restore capacity; the client offers manual retry and does not guarantee a precise countdown or automatic recovery. The prior disposable burst proves enforcement, not adequate public-launch capacity. HTTP 429 signals throttling ([RFC 6585](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)). Do not raise quotas or trust client-selected identities merely to mask contention.
